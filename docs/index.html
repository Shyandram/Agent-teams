The problem

A stalled agent looks
exactly like a working one

Run five agents in parallel and the hard part stops being the work — it becomes noticing which of them quietly stopped. An agent waiting on a permission prompt nobody can answer produces the same silence as one that is thinking.

!blockedneeds youWaiting on a permission prompt. Never resolves on its own — this is the one that costs an afternoon.
xerroredneeds youQuota exhausted, auth expired, or crashed. A rate-limited role stops producing output, which from outside is identical to having finished.
>workingActively producing. The transcript is still moving.
-idleAlive, nothing in flight. Waiting for work or for a message.
.stoppedSession ended. Its result block and token spend are still readable.

Composition

Parallelism only pays when
instances own different work

Two researchers with the same brief do the job twice. A catalogue of 66 assignments across 11 roles attaches by suffix, so each instance starts knowing what is its own.

# three researchers and two analysts, each on a different slice
agent-teams init --kind research \
  --roles "lead,research:survey,research:data,analysis:primary,analysis:ablation,qa"

# or two squads, each owning one direction end to end
agent-teams init --roles "lead,qa" \
  --squad "attn:research,analysis,engineering" \
  --squad "conv:research,analysis,engineering"

Squads decide internally without the lead, and are told not to converge on each other. If every squad lands on the same approach, the parallelism bought nothing.

Presets are deliberately small — solo 1, app-dev 3, research 4 — with -wide variants for work that genuinely splits. Every role is another full context to pay for and another thing that can wedge, so init warns above six.

The honest part

Four ways a fleet dies quietly

All four were found by running real fleets, not by reading documentation. Every one of them looks, from the outside, like an agent that is still working.

Untrusted directory

A background session in a directory that has never been trusted blocks on its first write — even with acceptEdits. launch refuses to start rather than spawning agents that wedge, and never sets the trust flag for you: that is a security control.

Chained commands

Permission matching applies to the whole command, so git add X && git commit matches neither an entry for git add nor one for git commit. The contract tells roles to issue one command per call — allowlisting every compound form is unwinnable.

Quota exhaustion

A rate-limited role stops producing output, which is indistinguishable from having finished the job. Rendered as errored, never as idle, and a hook can fire on it.

Work on a side branch

A background agent may relocate itself into a git worktree and commit there, so its work is not in your tree. close refuses to disband while commits sit in a worktree, and names which.

Install

One symlink

Claude Code and Codex read the same SKILL.md format, so one directory serves both. The CLI also works standalone by absolute path.

git clone https://github.com/Shyandram/Agent-teams.git ~/skills/agent-teams
bash ~/skills/agent-teams/agent-teams/install.sh

# then, in a project
agent-teams init --kind app-dev     # contract, aim, roles, permissions
agent-teams doctor                  # runtimes, auth, tmux, workspace trust
agent-teams launch --layout tmux    # survives disconnect; take a role over
agent-teams monitor                 # 127.0.0.1:8787

# from a laptop — the dashboard binds loopback and has no auth
ssh -L 8787:localhost:8787 user@your-linux-box
