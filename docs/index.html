The problem

A stalled agent looks exactly like a working one

Run five agents in parallel and the hard part stops being the work — it becomes knowing which of them quietly stopped. An agent waiting on a permission prompt nobody can answer produces the same silence as one that is thinking.

  • !blocked needs youWaiting on a permission prompt. Never resolves on its own. This is the state the dashboard is loudest about, because it is the one that costs you an afternoon.
  • xerrored needs youQuota exhausted, auth expired, or crashed. A rate-limited role stops producing output — from the outside, indistinguishable from having finished.
  • >working healthyActively producing. Transcript is moving.
  • -idleAlive, nothing in flight. Waiting for work or for a message.
  • .stoppedSession ended. Its result block and token spend are still readable.
  • ?unknownDeclared in the team manifest but never started.

Two modes

Forced by a constraint, not a preference

Native Claude Code teammates cannot be spawned headlessly — a -p session never spawns them. Anything that must survive an SSH disconnect or span runtimes needs a different mechanism, so there are two.

Mode A · in-session

Interactive, Claude Code only

Native teammates with the built-in mailbox and shared task list. Requires a TTY and a human in front of it. The skill prepares the roles and hands you the spawn prompt — it never fabricates team config, because that file is runtime state.

Mode B · detached fleet

Headless, all three runtimes

One process per role. --layout bg is background sessions and log files; --layout tmux gives each role an interactive window that survives disconnect and can be taken over mid-flight. Coordination happens through files, so Codex and pi roles participate identically.

Composition

Several instances, or several squads

Parallelism only pays when instances own different work. A focus catalogue of 66 assignments across 11 roles attaches by suffix, so two researchers never start with the same brief.

# three researchers and two analysts, each on a different slice
agent-teams init --kind research \
  --roles "lead,research:survey,research:data,analysis:primary,analysis:ablation,qa"

# or two squads, each owning one direction end to end
agent-teams init --roles "lead,qa" \
  --squad "attn:research,analysis,engineering" \
  --squad "conv:research,analysis,engineering"

Squads decide internally without the lead, and are told not to converge on each other. If every squad lands on the same approach, the parallelism bought nothing.

Honest part

Four ways a fleet dies quietly

All four were found by running real fleets, not by reading documentation. Each one looks like an agent that is still working.

What happensWhyWhat the tool does
Untrusted directory A background session in a directory Claude Code has never been trusted in blocks on its first write — even with acceptEdits. launch refuses to start, rather than spawning agents that wedge. It never sets the trust flag for you; that is a security control.
Chained shell commands Permission matching applies to the whole command, so git add X && git commit matches neither an entry for git add nor one for git commit. The contract tells roles to run one command per call. Allowlisting every compound form is unwinnable.
Quota exhaustion A rate-limited role stops producing output, which from outside is identical to having finished the job. Rendered as errored, never as idle — and a hook can fire on it.
Work on a side branch A background agent may relocate itself into a git worktree and commit there. Its commits are not in your working tree. close refuses to disband while commits sit in a worktree, and says which.

Shape of a run

Four commands

FIRST

init

Writes AIM.md, the AGENTS.md contract, roles, and a permission allowlist.

THEN

doctor

Runtimes, auth, tmux, and workspace trust. Fix anything red before launching.

THEN

launch

Starts the workers. The general is the seat you occupy, so it is skipped.

WHILE

monitor

Dashboard on loopback, reached through an SSH tunnel.

Install

One symlink

Claude Code and Codex read the same SKILL.md format, so one directory serves both. The CLI also works standalone by absolute path.

git clone https://github.com/Shyandram/Agent-teams.git ~/skills/agent-teams
bash ~/skills/agent-teams/agent-teams/install.sh

# then, in a project
agent-teams init --kind app-dev
agent-teams doctor
agent-teams launch --layout tmux
agent-teams monitor          # ssh -L 8787:localhost:8787 user@server

Requires bash 3.2+, Python 3.8+ (stdlib only), and one of claude / codex / pi. tmux optional. Windows: SSH to the Linux host or use WSL.
